Texas Hold'em for your group.
On your server, or ours.

Showdown is a No-Limit Hold'em table that runs in the browser. Create a table, share the link, play. The whole thing is one docker compose up and never talks to the outside world.

Play on play.showdown.kiunke.dev Self-host in 3 steps

The managed instance keeps a table and its link for one day. Self-host if you want history that lasts.

What you get

A complete cash-game table, nothing more, nothing less.

Real No-Limit rules

Side pots, short all-ins, min-raise logic and odd-chip splits done on the server. The client only renders.

Up to 10 seats, no sign-up

Players open the link, pick a name and an avatar, and sit down. A refresh or dropped connection returns them to their seat.

Voice chat and video built in

Browser-to-browser WebRTC, with an optional small camera tile per player. The server only relays the handshake and never carries audio or video.

Host controls

Whoever creates the table is the host: live settings, blind schedules, pause and end, kick, adjust chips, mute, chat moderation.

Log, replay, leaderboard

Every hand is logged and can be replayed step by step. Each table keeps its own leaderboard and final standings.

Private by design

Two containers, one SQLite file, zero external requests. The web client is a local WebAssembly build.

An honest shuffle

Cards are shuffled with Fisher–Yates driven by the operating system's cryptographic random source — the same code the live server deals with. A sample of 2,000,000 hands is tested against the theoretical distribution.

Testχ²p
Hand categories (8 df)8.790.360
Card positions (51 df)58.570.218

A p-value far above 0 means the deal is indistinguishable from a perfectly uniform shuffle. The second test looks for any of the 52 cards turning up more often than it should.

Checked after every event

Random play with all-ins, side pots, time-outs, re-buys, straddles and a moving button. After every single event the verifier re-checks:

  • ✓ chips in play never change during a hand
  • ✓ buy-ins minus cash-outs equal the chips on the table
  • ✓ no card is ever dealt twice
  • ✓ blinds and button sit where the rules say
  • ✓ only the player on turn can act
  • ✓ the offered fold/call/raise range is the legal one
  • ✓ illegal bets are refused and move no chips
  • ✓ main and side pots match a second calculation
  • ✓ every pot goes to the best eligible hand
  • ✓ split pots are equal and odd chips go clockwise from the button
  • ✓ each hand's winnings and losses cancel out exactly

Don't take our word for it

The verifier is in the repository. Clone it and run the whole thing yourself — the short run takes about ten seconds. 

git clone https://github.com/argseby/Showdown.git
cd Showdown && make simulate

What this does and does not show. The hand ranking is checked exhaustively — there is no five-card hand it has not seen. The rules and the chip arithmetic are checked over millions of random hands, which is evidence, not a proof. And none of it says anything about whether the person running a server is looking at the cards. That is why Showdown is built to be self-hosted: run it yourself and the deal is in your hands.

Self-host in three steps

All you need is Docker with the Compose plugin. The images come from GitHub's registry.

The images are published on GitHub's registry; nothing is compiled on your machine.

  1. Get the compose file

    mkdir showdown && cd showdown
curl -fsSLO https://raw.githubusercontent.com/argseby/Showdown/main/docker-compose.yml

  2. Optional: settings

    Port, table limit, retention, STUN/TURN servers for voice and video across networks, or IMAGE_TAG to pin a release.

    curl -fsSL https://raw.githubusercontent.com/argseby/Showdown/main/.env.example -o .env

  3. Start

    docker compose up -d

Open http://localhost:8080, create a table and share the link. Done. In Portainer: add a repository stack with compose path docker-compose.yml; updates are "re-pull image and redeploy".

Already running Traefik, nginx, Caddy or Dokploy? Point it at the web container on port 80 and let it terminate TLS. WebSockets on /ws/* must be forwarded.

  1. Join your proxy network instead of publishing a port

    Also download deploy/docker-compose.proxy.yml from the repository next to the compose file.

    cat >> .env <<'EOF'
PROXY_NETWORK=proxy-network
COMPOSE_FILE=docker-compose.yml:deploy/docker-compose.proxy.yml
EOF
docker compose up -d

  2. Or let Caddy handle HTTPS on its own

    If nothing sits in front of the stack and ports 80/443 are reachable from the internet (needs deploy/docker-compose.tls.yml).

    echo "SITE_ADDRESS=poker.example.com" >> .env
docker compose -f docker-compose.yml -f deploy/docker-compose.tls.yml up -d

Browsers only grant the microphone on HTTPS, so voice chat needs one of these two setups.

For development or a fork. The web image compiles the Flutter client: a few minutes and about 2 GB of disk.

  1. Clone the repository

    git clone https://github.com/argseby/Showdown.git
cd Showdown

  2. Copy the example environment

    cp .env.example .env

  3. Build and start

    make up is the same command.

    docker compose -f docker-compose.yml -f deploy/docker-compose.build.yml up -d --build

Releases are built by the repository's CI: pushing a tag v* publishes both images.

Questions

How long does a table on the managed instance live?

One day. After that the table, its link, hands and chat are deleted. Start a new table for the next session, or self-host to keep history.

Do players need an account?

No. A table link and a display name are all it takes. Names are chosen per table and are not identities.

Is it real money?

No. Chips are just numbers on the table. There is no payment, no wallet, no exchange of any kind.

Who can manage a table?

The browser that created it holds an admin key and sees an Admin tab. The key can be copied to another device. Anyone with the key can manage the table, so share it only with co-hosts.

How do I know the deal is fair and no chips go missing?

Every release is run through a verifier that plays millions of hands against the engine and re-checks the rules and the chip count after every single event — 207 million checks on the last run, with zero failures and not one chip created or lost. The summary is above and you can run it yourself with make simulate. It says nothing about the honesty of a server operator, which is the reason to self-host.

Does the server phone home?

Never. The API makes no outbound requests and the client is served entirely from your own instance. Voice and video only use a STUN or TURN server if you configure one.
